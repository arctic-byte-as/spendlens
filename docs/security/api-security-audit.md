## Standard route guard pattern

Authenticated routes now use a single shared guard helper (`src/lib/api/guard.ts`) to centralise session validation and return a consistent `401` response.

```ts
const auth = await requireAuthenticatedRouteContext()
if (auth instanceof NextResponse) return auth
const { supabase, user } = auth
```

This reduces drift risk where new routes accidentally omit auth checks.

## Stripe-specific security controls

- Webhook signature required (`Stripe-Signature`) and verified with raw request body.
- Idempotency/audit trail persisted in `stripe_webhook_events` (`event_id` unique).
- Duplicate Stripe events return success without replaying billing mutations.
- Duplicate Stripe events reprocess when prior state is non-terminal (`received`/`failed`) and short-circuit only for `processed`.
- Processing failures return `500` (retry-safe); signature failures return `400`.
- `mark_stripe_webhook_event` execution is revoked from public/anon/authenticated and granted only to `service_role`.

## Feature-flag tamper resistance

- `profiles.feature_flags` remains server-enforced in API gates.
- Column-level DB privileges revoke `UPDATE(feature_flags)` from `anon`/`authenticated`; only `service_role` can mutate rollout flags.
